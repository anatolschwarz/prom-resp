# Phase 2 #29 — Storybook asset pipeline

Implemented the smallest registry-driven Sunny Attic asset/rendering layer.

## Architecture

- `src/levels/partRegistry.ts` is the authoritative part vocabulary. It derives
  inventory keys and contact tags from registered entries, exposes narrow
  TypeScript types, and supplies runtime key/tag checks.
- `src/game/storybookAssets.ts` maps registered Storybook parts to Vite-loaded
  runtime assets. The two runtime PNGs are byte-for-byte copies of approved
  reference originals; `src/assets/storybook/README.md` records source paths and
  SHA-256 provenance.
- `src/game/storybookObjectProof.ts` declares exactly two generic proof objects:
  `mattress` and `teapot`. `PrototypeScene` loads them through one generic
  renderer when `?storybookAssetProof=1` is present; there are no object-named
  `createMattress` or `createTeapot` methods.

The proof renderer creates a Phaser image from content identity and a separate,
explicit Matter rectangle from `body` data. It does not inspect the image size,
trim, transparency, or silhouette when creating physics. Existing primitive
Ball/Ramp/Block rendering remains unchanged as the fallback/debug path.

## Inventory and safety

- Replaced the closed `{ ball, bird, block, ramp }` inventory interface with a
  `Record<InventoryPartKey, number>` derived from the registry.
- Mechanically migrated all five level JSON files, adding zero-count `mattress`
  and `teapot` entries without changing existing counts or gameplay.
- Contact tags now use the same registry-backed union and runtime validator.
  Unknown inventory keys and contact tags are rejected; arbitrary strings were
  not introduced. Actor typing remains deliberately `bird`-specific because #29
  does not add new actor behavior.
