## Root cause

`resetLevel()` calls `restoreLevelParts()`, which calls `destroyParts()`. For Ramp entries, `destroyParts()` removed the Matter-backed shape, contact registration, helper visuals, and map entry, but omitted the optional storybook `sprite`. The separate contact-destruction path already removed that sprite. Reset therefore left a live display object with no corresponding runtime or Matter object.

## Implementation

- Added a shared `destroyRamp()` lifecycle helper containing the complete Ramp teardown: contact unregistration, Matter/display shape destruction, helper visual destruction, storybook sprite destruction, runtime-map removal, and editable-component removal.
- `destroyParts()` now uses that helper for every Ramp in every puzzle, and `destroyRampFromContact()` delegates to it as well. This prevents divergent Reset and contact cleanup paths and makes repeated destruction inert.
- No level geometry, physics behavior, held-placement controls, Teapot/Cup behavior, or layout was changed.
