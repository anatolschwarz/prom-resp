Implemented Phase 2 milestone #28 (dynamic/toppling Block capability). Contraption-lab was not committed or pushed.

## Capability

A Block can now opt into being a Matter **dynamic rigid body** via two optional, declarative JSON fields — nothing character- or Painted-Block-specific:

- `dynamic?: boolean` — when `true`, the Block is a dynamic rigid body that can rotate/topple and transfer motion through collisions. Omitted or `false` keeps the historical static Block behavior, so every existing level is byte-for-byte unchanged.
- `rotation?: number` — initial rotation in radians (same convention as `RampDefinition`). Omitted means upright/axis-aligned (0). This is explicit gameplay geometry from the level JSON and is independent of any artwork silhouette.

Toppling and chaining are pure Matter physics acting on the Block's gameplay rectangle (`width`/`height`/`rotation`), not on any sprite. A dynamic Block rotates past its critical angle, settles on the floor, and pushes neighbouring dynamic Blocks — all deterministically.

## Design (and why it stays small — prompt item #10)

The capability is threaded through the existing seams rather than adding new machinery:

- **Schema/validation:** `BlockDefinition` extends `LevelPartDefinition` with the two optional fields; `validateLevel`'s `isBlock` guard gains two backward-compatible optional checks (`dynamic` boolean, `rotation` finite number). Legacy Blocks with neither field remain valid.
- **Rendering (`PrototypeScene`):** `createBlock` sets the body `isStatic: !dynamic` and applies the initial `rotation` on the Phaser GameObject before attaching the Matter body (the same ordering ramps already rely on). A dynamic Block's decorations (shadow/highlight/selection label) are re-synced from the live body each simulated step; `updateBlockSurface` rotates the decorative offsets. Both new code paths early-return for non-dynamic Blocks, and at rotation 0 the offset math is provably identical to the previous constants — so static Blocks render pixel-for-pixel as before.
- **Ownership/inventory:** untouched and orthogonal. `dynamic` composes with either `ownership: "fixed"` or `"player"`; `isPlayerPart`/`isEditablePart` are unchanged; level-defined Blocks (fixed or player) still do not consume tray Block inventory.
- **Reset (#5):** already recreates every Block from JSON via `createBlock`, which now restores position, `rotation`, and dynamic-body state (a fresh body at rest). No change needed beyond `createBlock` honoring the new fields.
- **Rerun (#6):** the run-start snapshot recreates each Block as a fresh Matter body at its captured transform with zero velocity. Because the world is paused during editing and Blocks are not player-rotatable, run-start is always a **rest** state, so linear/angular velocity are 0 and need no separate serialization — recreating from (position, rotation, zero velocity) reproduces the exact deterministic replay. Matter is bit-exact deterministic here, confirmed by the repeat-run test.

**One fidelity fix beyond the JSON fields:** `captureRunLayout` previously recorded each Block's live `x,y` but the *definition* rotation. There is a wired **Edit** button that returns to edit mode after a run without a Reset, so a Block left toppled can reach a new run-start at a non-JSON angle. To satisfy "#6 restores the exact run-start rotation" in that reachable path, the Block snapshot now captures `block.shape.rotation` (the live angle), exactly as the ramp snapshot already does. For a Block that has not toppled, `shape.rotation === definition.rotation`, so the dominant path and all static Blocks are unchanged.

## Tests added (`tests/dynamicBlock.test.ts`, 12 cases)

Schema/validation (accepts + preserves `dynamic`/`rotation`; legacy Block valid; rejects non-boolean `dynamic` and non-finite `rotation`); ownership/inventory (orthogonal to ownership, classification unchanged, inventory not consumed); headless behavior (static default stays exactly in place; a leaning Block topples further and settles lower; motion transfers to a neighbouring dynamic Block via a `block:a`↔`block:b` contact; repeat runs are byte-identical; Reset reconstructs the exact initial JSON transform).
