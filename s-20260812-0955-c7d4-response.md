Implemented milestone #26 — Contact Actions v2.

Architecture: shared capability-based `contactRules` executor. Rules use declared contact-role selectors (`{ type: "contact", index: 0 | 1 }`) or an exact participant-id selector; legacy destroy tag targets remain compatible. Browser and headless Matter adapters register id/tag/capabilities and use the same executor plus vector helpers.

Files changed: `docs/CODEX_PROMPTS.md`; `src/levels/levelTypes.ts`, `src/levels/validateLevel.ts`; `src/game/contactRules.ts`, `src/game/PrototypeScene.ts`, `src/game/headlessSimulation.ts`; `tests/contactRules.test.ts`, `tests/levelValidation.test.ts`, `tests/headlessSimulation.test.ts`.

Semantics: impulse adds its world-space vector to the selected participant's current Matter velocity. Redirect normalizes its non-zero direction and replaces velocity direction while preserving scalar speed; stationary participants stay stationary. Optional `participant-id` conditions compare a selected contact participant's registered id exactly; all conditions must pass. Matching rules execute in JSON order; a destroyed participant is skipped by later rules in that contact.

Extensibility: the executor has no Ball/Bird/etc. branches; it dispatches only action types to registered participant capabilities. Adding/removing an object type requires its declarative tag/validation and runtime registration, not contact-engine edits. Same-tag contacts can target a participant unambiguously by id.

Tests/validation: focused contact, validation, and headless tests passed; full `npm run typecheck`, `npm run lint`, `npm test` (12 files, 104 tests), `npm run format:check`, `npm run build`, `npx playwright test --list` (17 tests), and `git diff --check` passed. Build emitted only the existing Phaser chunk-size warning.
